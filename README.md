# Agent Skills

Колекція переносимих Agent Skills для Codex, Claude Code та інших агентів, які підтримують формат `SKILL.md`.

Це **публічний каталог**. Репозиторій містить лише загальнодоступні skills, їхні довідкові матеріали, шаблони та автоматичну перевірку структури. Службові й внутрішні skills зберігаються окремо у приватному репозиторії. Звичайні одноразові промпти, якщо вони з'являться, слід зберігати окремо від `skills/`.

## Каталог

| Skill | Доступ | Призначення |
|---|---|---|
| [`business-grill`](skills/business-grill/) | Public | Доказова перевірка бізнес-гіпотез, інвестицій, операційних моделей і кошторисів з рішенням GO / VALIDATE / PIVOT / STOP та фокусом на делегованість. |

## Поділ public/service

- **Public:** універсальні skills без службових даних, реальних внутрішніх схем, закритих процедур, приватних шляхів або ідентифікаторів. Зберігаються в цьому репозиторії.
- **Service:** skills для службової, внутрішньої чи обмеженої діяльності. Зберігаються тільки в окремому приватному репозиторії.
- **Public core + private profile:** універсальна методика може бути публічною, а службові форми, довідники, схеми даних і конкретні правила — приватним адаптером.

Перед створенням нового skill прочитайте [CLASSIFICATION.md](CLASSIFICATION.md). Якщо є сумнів, skill класифікується як **Service** до окремої перевірки на публікацію.

## Структура

```text
agent-skills/
├── skills/
│   └── business-grill/
│       ├── SKILL.md
│       ├── README.md
│       ├── agents/
│       ├── assets/
│       └── references/
├── scripts/
│   └── validate-skills.py
└── .github/workflows/
    └── validate-skills.yml
```

Кожна папка безпосередньо в `skills/` є самодостатнім skill. Її можна копіювати окремо без залежності від решти репозиторію.

## Встановлення

### Codex

Скопіюйте потрібну папку skill до персонального каталогу:

```text
%USERPROFILE%\.codex\skills\<skill-name>
```

Почніть нову сесію та викличте skill явно, наприклад:

```text
Use $business-grill to stress-test this business hypothesis.
```

### Claude Code

Для персонального використання скопіюйте skill до:

```text
~/.claude/skills/<skill-name>
```

Для одного проєкту:

```text
.claude/skills/<skill-name>
```

Після копіювання почніть нову сесію.

## Перевірка

Локально:

```powershell
python scripts/validate-skills.py
```

Перевірка запускається автоматично для кожного push і pull request. Вона контролює назву папки та frontmatter, обов'язкові поля, незавершені TODO і локальні Markdown-посилання.

## Правила додавання skills

1. Назва папки та поле `name` мають збігатися і використовувати лише `a-z`, цифри та дефіси.
2. `description` має пояснювати, що робить skill і коли його застосовувати.
3. Основні правила належать у `SKILL.md`; великі умовні матеріали — у `references/`; шаблони результатів — у `assets/`.
4. Skill має бути самодостатнім або явно документувати залежності.
5. За замовчуванням не надавати агенту ширших повноважень, ніж потребує завдання.
6. Спочатку визначити клас за [CLASSIFICATION.md](CLASSIFICATION.md); службові skills не додавати до цього репозиторію навіть у спеціальну папку.
7. Не додавати секрети, персональні дані, приватні абсолютні шляхи або неперевірені клієнтські твердження.
8. Перед публікацією перевіряти зовнішні джерела та ліцензійні умови.
