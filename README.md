# Agent Skills

Колекція переносимих Agent Skills для Codex, Claude Code та інших агентів, які підтримують формат `SKILL.md`.

Репозиторій містить завершені skills, їхні довідкові матеріали, шаблони та автоматичну перевірку структури. Звичайні одноразові промпти, якщо вони з'являться, слід зберігати окремо від `skills/`.

## Каталог

| Skill | Призначення |
|---|---|
| [`business-grill`](skills/business-grill/) | Доказова перевірка бізнес-гіпотез, інвестицій, операційних моделей і кошторисів з рішенням GO / VALIDATE / PIVOT / STOP та фокусом на делегованість. |

## Структура

```text
agent-skills/
├── skills/
│   └── business-grill/
│       ├── SKILL.md
│       ├── README.md
│       ├── agents/
│       ├── assets/
│       └── references/
├── scripts/
│   └── validate-skills.py
└── .github/workflows/
    └── validate-skills.yml
```

Кожна папка безпосередньо в `skills/` є самодостатнім skill. Її можна копіювати окремо без залежності від решти репозиторію.

## Встановлення

### Codex

Скопіюйте потрібну папку skill до персонального каталогу:

```text
%USERPROFILE%\.codex\skills\<skill-name>
```

Почніть нову сесію та викличте skill явно, наприклад:

```text
Use $business-grill to stress-test this business hypothesis.
```

### Claude Code

Для персонального використання скопіюйте skill до:

```text
~/.claude/skills/<skill-name>
```

Для одного проєкту:

```text
.claude/skills/<skill-name>
```

Після копіювання почніть нову сесію.

## Перевірка

Локально:

```powershell
python scripts/validate-skills.py
```

Перевірка запускається автоматично для кожного push і pull request. Вона контролює назву папки та frontmatter, обов'язкові поля, незавершені TODO і локальні Markdown-посилання.

## Правила додавання skills

1. Назва папки та поле `name` мають збігатися і використовувати лише `a-z`, цифри та дефіси.
2. `description` має пояснювати, що робить skill і коли його застосовувати.
3. Основні правила належать у `SKILL.md`; великі умовні матеріали — у `references/`; шаблони результатів — у `assets/`.
4. Skill має бути самодостатнім або явно документувати залежності.
5. За замовчуванням не надавати агенту ширших повноважень, ніж потребує завдання.
6. Не додавати секрети, персональні дані, приватні абсолютні шляхи або неперевірені клієнтські твердження.
7. Перед публікацією перевіряти зовнішні джерела та ліцензійні умови.
